## `recap_check.py` vs this review

Running `python extra/recap_check.py workers/output/bad-recap.md` exits with code 1. It reports 10 FAIL and 3 WARN lines:

- FAIL: frontmatter missing `attendees` and `source`, the file name, the title, all four template sections missing, and L9 `frustrated` and `agency fees`.
- WARN: the account slug isn't in the file name, the file isn't saved under `brain/knowledge/meetings/`, and L9 `fees`.

**The checker caught nothing that this review missed.** Every FAIL and WARN it reports is covered by rows 2 and 13 to 15 above. Row 1 is only partly covered: the checker fails L9 because of the words "frustrated" and "agency fees". It doesn't know the sentence came from a DM.

**This review caught things the checker missed:**

- **GMV (rows 5 and 6).** The checker only runs its performance-number rule on files under a `brain/` path, so it never looked at L9's `$95K GMV`. That limit was added on purpose, so `proposed-changes.md` wouldn't get false positives. I ran the checker on a temporary copy saved as `...\brain\knowledge\meetings\2026-09-15-loop-athletic-weekly.md`, and it then reported "L9 performance number typed, link the sheet instead". So a draft passes this check until it lands in the brain. Even then, the checker doesn't compare the number with the sheet's 62000, so it can't tell there's a conflict to flag.
- **DM provenance (rows 1 and 3).** The checker reads only the recap, never the transcript. It catches L9 only because of keyword luck ("frustrated", "agency fees"). It misses L14 "Keep an eye on the account review risk" completely. A rewrite such as "Theo's leadership may revisit the relationship in Q1" would pass the checker and still leak the DM.
- **Missing held-back flag (row 4).** The checker requires a `## Flags for a person` heading, but it doesn't check that the section says something was held back.
- **Owners and due dates (rows 7 and 8).** The checker's owner and due-date checks run only on table rows. With no table, it reports "missing section" and nothing more. It can't tell that Friday 2026-09-18 was promised to the client.
- **Earlier meeting (rows 9 to 11).** The checker has no rule for house rule #5 and doesn't read earlier recaps. So it can't see the size-chart action from 10 Sep, or that the try-on decision was already made.
- **Content quality (rows 6, 12 and 16).** The checker doesn't look at false precision, filler, unattributed client claims, or follow-ups to the account page.

## Root cause

The recap follows `workers/skills/skill-recap.md`. That skill says "Include everything relevant, so nothing gets lost" (step 2) and "Include the key numbers mentioned on the call" (step 3). It never points to `RESOLVER.md` or `SANITIZER.md`, and it says "Post it" (step 5) without running a check first. Following those steps produces rows 1 to 3 and row 5. The skill should be fixed so this doesn't happen again.
